Geodetic network adjustment, inside QGIS.

GeoComp takes a survey from field observations to an adjusted network whose results have been statistically checked, and puts the answer on the map — total station, levelling, GNSS, gravimetry, and repeated surveys of the same network over time.

Install the plugin Source on GitHub

What it does

Every step is a QGIS Processing algorithm, so it runs from the menu, the toolbox, the modeller or a script, and every result keeps a record of how it was made.

Total station

Field-book import with saved column mappings, face reduction, atmospheric and EDM corrections, traverse, resection, intersection, trigonometric levelling, and classical network adjustment.

Levelling

Level-book import, closure checks, equal, equidistant and extreme sight methods, and a levelling network adjustment.

GNSS

Absolute and relative, static and kinematic processing with RTKLIB; precise products discovered and downloaded; baselines built into a network; configurations compared.

Gravimetry

Reduction of relative gravimeter readings for scale, Earth tide and drift, then a gravity network adjustment.

Integration

GNSS with total station, total station with levelling, GNSS with levelling, or several techniques at once, in one adjustment with per-technique variance components.

Monitoring

Compare two epochs, test reference-point stability, build time series with alert thresholds, and report.

Behind them: the adjustment core estimates, tests and explains — global test, data snooping, reliability, error ellipses, with uncertainty carried through every step rather than attached at the end. 48 algorithms in all, in English, Portuguese (Brazil) and Spanish.

Two examples you can run in minutes

Both ship inside the plugin: GeoComp ▸ Project ▸ Install tutorial dataset copies them to a folder you choose, each with a walkthrough.

A network adjustment, with two real errors

The author's own total-station triangle: three stations, each observed on both faces. It contains a 1.000 m transcription blunder that pre-processing catches, and a global test that correctly fails. Software that finds real errors in real data teaches more than a clean run.

A GNSS baseline, end to end

RTKLIB's own 2005 sample: two receivers 3.3 km apart. Discover the session, run the engine, read the solution — 120 epochs, 117 with ambiguities fixed — and see it on the map. GeoComp carries the rnx2rtkp program itself, so there is nothing else to install.

Install

Needs QGIS 4.0 or later. This is a pre-release; there is no listing on the QGIS plugin repository yet.

  1. Get geocomp.zip: from the project's Releases page when one is published, or the geocomp-plugin artifact of the build workflow on GitHub Actions.
  2. In QGIS: Plugins ▸ Manage and Install Plugins ▸ Install from ZIP, choose the file, and install. Because it is experimental, enable Show also experimental plugins under Settings if it does not appear.
  3. A GeoComp menu appears, and the algorithms are in the Processing toolbox.

Where it stands

A research project of the Departamento de Geomática, Universidade Federal do Paraná, built from a written specification and checked against published reference data wherever that data could be reached.

Early software. The adjustment and statistics are tested against textbook and published networks; the GNSS example above shows the pipeline running, not that its coordinates are accurate — the two sample stations have no published coordinates to compare with. It has not had a stable release, and the QGIS plugin repository does not list it.
  • The specifications, decision records and a requirement-by-requirement acceptance register, with what is not met stated plainly, are in the specs folder.
  • Open source, GPL-2.0-or-later. Issues and contributions are welcome on GitHub.
